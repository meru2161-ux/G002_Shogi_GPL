# 1. 製品としての完成像と範囲

## 1.1 必須の二つの体験

**指導モード**：ユーザーが考えて指すことが主役。指した後に一手の評価、理由、注意点、相手の代表応手、進め方、より良い候補を示す。答えを最初から選ばされるだけのアプリにしない。必要なときは着手前にもヒントを見られる。

**AI対局モード**：余計な解説に遮られず、自然な駒操作でAIと一局を指せる。先後・強さ・時間条件を選び、中断保存・再開・終局・振り返りまで完成させる。

両方が同じアプリ、同じルール基盤、同じ盤操作品質を使う。モードの片方をデモ扱いにしない。

## 1.2 製品版必須と後回しの線引き

- **P0（安全・正確性必須）**：合法手、駒打ちと成り、所有者の向き、手番、終局、データ保持、先生の重大な誤断定防止、クラッシュ・状態破損防止。
- **P1（製品体験必須）**：完成した二モード、実用的な棋力、三つの対戦難易度、盤と駒の視認性、分かる説明、保存・再開・棋譜振り返り、最小の時間設定、設定・ヘルプ・公開準備。
- **P2（本版では実装しない）**：オンライン対人戦、段級位認定、ランキング、クラウドLLM、広告・課金、アカウント、音声会話、豪華3D演出、駒落ち、詰将棋問題集、無制限なテーマ収集。

P1は「できれば」ではない。本製品の完成判定ではP0とP1を満たす。P2を増やしてP0/P1を先延ばしにしない。

# 5. 駒・盤・持ち駒のビジュアル仕様

## 5.1 描画の必須条件

- 駒の輪郭、文字、縁取りを一つのグループとして所有者・視点に応じて回す。文字だけ180度、輪郭は同じ向き、左右ミラーはすべて不合格。
- 手前の自駒の先端は奥、相手駒の先端は手前を向く。敵陣へ進んでも所有者で向きを決める。持ち駒を打つと新所有者の向きになる。
- 持ち駒の「×3」等とラベルは回さない。数字は駒の描画グループ外に置く。
- 視点反転は論理座標・先後・棋譜を変更しない。描画とタップ変換の逆写像をテストする。
- 駒の陰影は弱く、全体の光源を統一する。強い立体表現で文字やマスの意味を隠さない。[S10]

## 5.2 五角形・文字

駒は高さに対して上へ尖る五角形。初期比率の目安は駒幅=マス幅の0.82、駒高=マス高の0.90、先端=高さの上端、肩=高さの0.16、底辺=0.92付近。これは調整開始値であり、実画面の可読性を優先して整える。

標準は読みやすい一文字主体：王／玉、飛、角、金、銀、桂、香、歩、龍、馬、と。成銀・成桂・成香は既存の一文字略字を使う場合もヘルプと読み上げで区別し、分かりにくければ小さめの「成」＋元駒字に統一する。小さい字が潰れる書体や独自な崩し字を必須にしない。

成駒は表記を変え、補助として朱色を使用。赤色だけ変えて同じ文字にすることは禁止。玉と王は同じ能力で、文字の違いをAIの強弱や所有者の判定に使わない。

## 5.3 美術指針

主題は「落ち着いた木製将棋盤」。抑えた木目、温かい駒、細く明瞭な線。市松模様、強い光沢、蛍光色、余計な宝石・金属装飾は使わない。木目はキャッシュし、フレームごとの乱数生成や大容量画像を避ける。

デザイントークンに盤色、駒色、線色、文字、朱、アクセント、余白、角丸を集約する。駒字にはライセンス確認済みの既存フォントを使い、他アプリの駒画像や専用字体を抽出しない。最初は標準木製と高コントラスト設定で完成させ、多テーマ収集へ広げない。

## 5.4 状態表示と重なり順

| 状態 | 色以外の識別 | 優先 |
|---|---|---|
| 選択駒 | 輪郭枠 | 最優先 |
| 合法な空きマス | 小さな点 | 入力中に優先 |
| 合法な駒取り先 | マスの角枠 | 入力中に優先 |
| 直前手 | 元・先の薄い面 | 常時控えめ |
| 候補手 | 原則1本の矢印 | 説明・比較中 |
| 王手 | 玉への注意枠＋「王手」 | 必ず認識可能 |

矢印が駒字を完全に隠さない。手を指そうとしている間は候補矢印を薄くするか一時非表示にする。駒打ちは架空の盤上移動元を作らず、持ち駒チップと着地点を対応表示する。

## 5.5 持ち駒

相手は上、自分は下。飛・角・金・銀・桂・香・歩の順に一貫表示する。存在する種類をチップ＋枚数で表示し、ゼロなら「なし」。最悪7種類でも全部へアクセスできるよう横スクロールまたは2行で収める。横スクロールの存在を隠さない。選択は駒種IDで保持し、並びの変更で別駒へすり替わらない。

自分の手番に自分の駒だけを選べる。選択時は「銀を打つ場所を選んでください」と表示する。同じチップを再タップで解除できる。持ち駒が消費されて0になる、新局、モード変更、取消で選択状態を正しくクリアする。

# 6. 共通操作仕様 — 誤操作で局面を壊さない

1. 自駒タップで選択。合法な移動先を提示する。
2. 別の自駒タップで選択変更。同じ駒タップまたは戻るで解除。
3. 合法先タップで盤上移動を要求する。駒打ちは別型の要求にする。
4. 盤上移動の成り・不成が両方合法なときだけ成り選択を表示する。
5. 強制成りは成って確定。不成だけ合法なら確認なし。駒打ちには成り欄自体を作らない。
6. 不正な要求は拒否して理由を短く示す。盤・持ち駒・履歴・手番・AI起動を変更しない。
7. 確定した一手は一度だけ原子的に適用する。連打・古い選択・再送・画面復帰で二重着手しない。

ドラッグ操作は本版必須ではない。タップ操作をまず完成させる。既にドラッグがあれば同じ着手要求へ流し、別ルールを作らない。通常の対局着手確認はOFFを初期値とし、設定で毎手確認ONにできる。成り選択と毎手確認を不要に二重表示しない。

AI思考中のユーザー着手は受け付けないが、メニュー・中断・設定・棋譜は固まらない。エラー表示が繰り返し積み上がったり、音が連打されたりしない。

「戻る」を曖昧に使わない：画面を戻す／選択取消／読み筋を1手戻す／実対局の待ったを区別し、文言とUIの位置を変える。

# 7. 採用ルール・終局・時計

詳細な平手ルールは付録Aに含める。既存ルール正本と照合し、公式情報に反する内容があれば根拠とともに修正する。指導・対局・解析・UI・棋譜入力は同じ合法手基盤を使う。[S01–S07]

## 7.1 製品のルールプロファイル

新規対局の本書標準は、平手の共通規則＋日本将棋連盟型の入玉宣言（31点勝ち／24～30点指し直し）＋500手規定。`G002_STANDARD_JSA_V1`等の固定IDと版を棋譜に保存する。

- 入玉しただけで終了しない。条件の確認と宣言確定を分ける。
- 相互合意による持将棋、27点宣言等は別方式であり、数値を混在させない。本版の新規対局の選択肢は上記1種類に絞る。
- 既存の保存局が別の明示されたRuleProfileを持つ場合、その局を途中で新規標準へ変えない。旧規則で再開できない場合は閲覧専用として保持し、ユーザーへ説明する。
- 待った・ヒント・中断中の時計停止は、G002のローカル学習機能であり公式棋戦ルールそのものとは表示しない。

## 7.2 終局イベント

詰み、投了、通常千日手、連続王手千日手、入玉宣言の成功・失敗、500手規定、時間切れを別enum等で扱う。勝者がいない結果と敗北を混同しない。単なる評価値、探索失敗、一定手数でAIが飽きたことを終局に使わない。

指し直しは前局を保存して先後交代の新局を作る。G002のローカル対局では時間を新局の設定へリセットすることを明記する。終局後の盤は閲覧・研究可能だが本対局へ追加着手しない。

イベント処理は一元化する。着手前に期限・手番を確認し、確定手適用後は詰み・反復等を判定する。既に成立した詰みを、遅れて届いた投了や探索結果で上書きしない。判定が同時に見える場合も処理順を単体テストで固定する。

## 7.3 最小の時計機能（P1）

指導モード：時間無制限のみ。通常AI対局：時間無制限／各10分＋1手30秒の秒読みを提供する。自由な時計編集、フィッシャー、複雑な大会制度はP2。

- 単調時計を使う。1秒ごとの加算・減算だけで時間を管理しない。
- 成り選択・着手確認中も自分の時計は進む。着手が確定した時刻で消費を確定する。描画アニメ時間は消費へ上乗せしない。
- 持時間が尽きた手では残り消費を30秒へ適用し、以降各手で秒読み30秒をリセットする。残り秒数を繰り越さない。
- 着手確定の単調時刻が期限以上なら時間切れ。境界直前・一致・直後をテストする。
- オフラインのためアプリがバックグラウンドへ移ると双方時計と探索を停止し、保存する。復帰時は「再開」まで進まない。この仕様を時間設定の説明に書き、競技用厳密時計とは呼ばない。
- AIも自身の残時間内で指す。探索予算に上限と安全余裕を持ち、異常時に無制限に待たない。

# 8. 指導モード — 指した後に学ぶ

## 8.1 標準の一巡

`ユーザーが考える → 駒を指す → 一手レビュー → AIの応手を見る → AI着手 → 相手の狙い → 次のユーザー手`

着手前のヒントは初期OFF。自分で考える時間を尊重する。「ヒント」を押せば原則3候補、各候補の矢印と理由を見る。合法手が1～2なら実在する数だけ表示する。

## 8.2 着手後レビュー

確定したユーザー手の前局面・後局面・局面ID・手数を保存し、その手を強い先生設定で評価する。候補一覧にない手も評価対象にする。

標準カードは次の順：
1. 「あなたの手：▲○○」と良否ラベル。
2. 根拠となる理由を2～3行。
3. 狙い／注意点／相手の代表応手を折りたたみ可能に表示。
4. 「読み筋」「別の手と比較」「指し直す」「AIの応手を見る」。

ラベルと理由は切り離さない。レビューが出た瞬間にAIが指して文章が流れて消える挙動は禁止。標準は読んでから「AIの応手を見る」を押す。設定で自動応手に切替可能にする場合も、レビューは履歴に固定して読み直せるようにする。確認を増やすためだけの追加ダイアログは作らない。

## 8.3 相手の応手と次の局面

先生が例示した応手と、難易度に応じて相手AIが実際に選んだ応手は一致するとは限らない。実際に指された手に対して説明を生成し直す。相手の手がPVと違うのに前の説明を流用しない。

新局面を解析し直し、ユーザーの次の入力が可能な状態へ戻す。評価が未完了でも盤は描き、解析中・取消を表示する。候補を出すためだけに長時間入力を禁止しない。

## 8.4 「相手がこう指したら？」

現在表示している読み筋から相手の手番の局面へ進み、相手の別の合法手を選んで再解析できる。既存PVを見せるだけでこの機能を実装済みとしない。

分岐は本対局から隔離し、「検討中」と表示する。「本対局に戻る」で手番・盤・持ち駒・レビューを正確に復元する。分岐を本筋へ採用するのは明示的な「この局面から練習」で新しい練習局を作る場合だけ。

## 8.5 指し直しと終局後

指導モードでは自分の直前の意思決定まで戻れる。AI応手済みなら原則2手、未応手なら1手を戻し、反復履歴・評価セッション・時計・先生コメントを整合させる。旧手順は分岐として保持する。

終局後は「今回よかった手」「改善したい場面」「次に意識すること」を各最大3件、実際の棋譜と根拠付きで提示する。抽象的な褒め言葉だけで終えない。根拠が弱ければ件数を水増ししない。

# 9. 通常AI対局 — 普通の将棋ゲームとして完成させる

## 9.1 対局設定

先手／後手／ランダム、入門／標準／強め、時間無制限／10分＋30秒を選べる。ランダム先後は毎局決めて棋譜へ保存し、アニメーションの再実行で結果を変えない。

標準はヒントなし、評価グラフなし、長文レビューなし。自分を画面下へ置き、AIが先手なら新局後に1手だけ指す。待ったは設定で許可でき、初期OFF。「待ったあり」の練習条件を対局情報に残す。レーティングや公式成績は本版では計算しない。

## 9.2 AIの振る舞い

すべての難易度で合法手を指す。難易度の差は探索や良手選択で作り、二歩、王手放置、玉の捕獲、駒の増殖を弱さの演出に使わない。

基本は最後まで指す。AIの早期投了で「なぜ勝ったか分からない」を初期状態にしない。投了設定を後で加える場合は持続した十分な解析根拠を条件とし、評価値一回だけで投了しない。

投了・中断・新局に分かりやすい導線と確認を持たせる。新局後の手数は0、前局のAI結果は無効。対局時計がある場合の手番交代も一回だけ。

# 10. 棋力仕様 — エンジン名や速度だけでは合格にしない

## 10.1 現在のエンジンの扱い

現在の軽量Negamax／Alpha-Beta／Iterative Deepening実装をまず測定する。自作であること、戦法名を認識すること、テストが87件通ることは棋力の証明ではない。

このエンジンが本章の基準を満たせば採用を続ける。満たさない場合は原因を改善するか、使用条件が確認できる既存エンジン・評価方式を比較する。弱い状態を「軽量だから十分」と言い換えて品質を下げない。

外部エンジン再検討はベンチマークで必要性が示されたときに絞る。旧Sunfish4調査を無限に繰り返さない。候補は最大3、調査は時間枠を定める。エンジン本体、評価データ、定跡、依存、JNIの利用条件を分離して記録する。GPL等がG002本体の公開方針へ影響する選択は、勝手に本体ライセンスを変更せず具体案を一度提示する。[S19][S20]

## 10.2 先生と相手AIの分離

先生の解析予算は相手の難易度から独立する。相手が入門でも先生が意図的に悪い候補を教えない。同じエンジンでも設定と結果の由来を分ける。

候補は原則上位3つの異なる合法なRoot Move。成りと不成は異なる手。候補ごとの読み筋・スコア・深さ・時間・打切り・エンジン版・Root局面を保持する。探索の境界値を正確な順位差として誤用しない。

## 10.3 数値評価・ユーザー手の比較

概念式：
`損失 = 最良候補の評価（ユーザー視点） - ユーザー手の評価（同じ視点）`

後局面を手番側視点で評価している場合は符号の変換を一度だけ行う。前後で異なる評価単位やdepthを雑に引かない。必要なら同じRootでユーザー手に限定した探索を行う。探索制限・境界値・未完了の結果には信頼度を付け、比較不能なら評価保留とする。

mateスコアは通常の数値と別型。詰む側・手数の扱いを固定する。「mateに近い大きな数」だけで詰みを断言しない。読み筋は適用のたびに合法性を検証し、不正・欠損なら途中で止めて未完了表示する。

## 10.4 棋力受け入れデータセット（G002の製品基準）

既存ケースを活用し、基礎戦術60局面＋戦法・囲い・説明30局面を固定する。盤面／SFEN、手番、既知の正解または許容手集合、悪い例、根拠、作成者・検証方法を保存する。無断で棋書・問題集を大量コピーしない。反転版だけで件数を水増ししない。

基礎戦術60の内訳目安：一手詰み10、短い詰み回避10、即時の取り返し・駒損10、成り・不成と駒打ち10、王手回避と合駒10、3～5手の戦術10。

先生標準の必須基準：
- 全候補・全PVの合法性100%。
- 一手詰み・唯一の王手回避・明白な一手詰み回避等、正解が独立確認できるP0群は100%。
- 60局面全体で許容手を3候補内に含む割合90%以上、最上位が許容手の割合80%以上を初期の合格下限とする。
- 短い強制手順が保証されるケースで、危険な手を「良い手」と強く断定する誤り0件。
- 30の戦略説明では、駒取り・成り・所有者・利き等の事実誤り0件。根拠があるときに具体的な説明を出せるケース90%以上。すべて保留にして逃げない。

これらの合格率は本書の品質目標で、一般的な段級位換算ではない。数値に合うようテストを簡単な局面へ差し替えない。落ちたケースを保存し、独立検証した正解の誤りが判明した場合だけ根拠付きで訂正する。

さらに序盤・中盤・終盤の保存局面から通常対局を複数走らせ、意味のない往復、明白な駒損、玉の危険放置がないか棋譜で確認する。外部の強い解析器を照合に使う場合は、版・設定・予算を記録し、最善手一致だけを唯一の正解にしない。

## 10.5 難易度の差

入門／標準／強めが名称だけ違う状態にしない。同じ開始局面群を先後交代して、上の段階が下の段階へ一貫して優位を示すかを確認する。最低20組の比較対局を固定seedと予算で記録し、結果は勝敗・引分け・時間上限を分離する。

統計的に差が判断できなければ、同等なのに三段階完成とはしない。調整する。段級位・Elo・他製品と同じ強さは、独立した較正なしに表示しない。

# 11. 先生の解説仕様 — 根拠を盤上へ結び付ける

## 11.1 説明データ

説明は単なる文字列ではなく、少なくとも次を保持する。
`局面ID、対象手、事実、解釈、根拠マス、根拠PV、比較条件、確度、生成版、表示用短文／詳細`

事実：王手した、銀を取った、歩を打った、角道が開いた等。
解釈：攻めの準備、囲いを崩す可能性、次の目標等。局面とPVが支えるときだけ出す。戦法名だけで「勝ち筋です」としない。

## 11.2 良否ラベル

表示語は「良い手／自然な手／注意が必要／悪手／評価保留」を基本とする。非難ではなく手の評価として説明する。「悪手」を単に隠して曖昧にするのではなく、損失と具体的な相手の応手に根拠がある場合に使う。

閾値はエンジンの評価尺度に合わせて一元化し、固定ケースで較正する。他のエンジンのcp値をそのまま流用しない。上位候補に一致しただけで「最善」、候補外だから「悪手」、戦法名が付いたから「良い」は禁止。

根拠が薄い場合は「この解析では優劣を確定できません」とし、確認できた事実と合法な候補だけを伝える。時間が足りなければ「詳しく調べる」で追加解析できる。

## 11.3 質問への対応

| 操作 | 必ず変わる内容 |
|---|---|
| なぜ？ | 対象手の効果、守る地点・取る駒・開く利き等を具体表示 |
| 他の手は？ | 同じRootの別候補と矢印・理由を切替 |
| この手の注意点 | 代表応手と危険箇所。危険が未確認ならそう表示 |
| 読み筋を見る | 合法なPVを1手ずつ動かす |
| 相手がこう指したら | 合法な別応手の分岐を作り、その局面を解析 |
| 別の手と比較 | 自分の手と別候補を同じ前局面で比較 |
| 自分で考える | 着手前のヒントを隠す。指した後のレビュー設定は維持 |

## 11.4 勝ち筋・負け筋の言い方

原則の見出しは「この手からの進め方」。短いPVだけで勝利保証をしない。相手の協力が必要な手順には「相手がこの応手なら」と条件を付ける。詰みの全回避を検証できた場合だけ「詰みがあります」とする。

駒を取った直後に取り返されるなら、交換全体の説明をする。銀の成りで後斜めへ動けなくなる等、動きを失う側面も必要時に説明する。棋譜・盤面と一致しない固有の手順をテンプレートで流用しない。

## 11.5 戦法・囲い認識

居飛車、各振り飛車、矢倉、美濃、棒銀等は特徴集合と適用条件で認識する。「飛車がその筋に一瞬いた」「金銀が近い」だけで確定しない。形成中、崩れた後、攻防で位置が変わった場合を区別する。

戦法理解の表示は副情報とし、現在の手の具体的な説明を主役にする。利用者を上から叱る、人格や才能を判断する表現は使わない。

# 12. 対局状態・非同期処理・復帰

## 12.1 一つの状態機械

概念状態：
`SETTING_UP → HUMAN_TURN → PROMOTION_PENDING? → COMMITTING → REVIEWING（指導のみ） → ENGINE_TURN → HUMAN_TURN … → FINISHED`
別の表示状態：`BROWSING_RECORD / EXPLORING_VARIATION / PAUSED / ERROR_RECOVERABLE`。

| イベント | 許可条件 | 結果 |
|---|---|---|
| 駒選択 | HUMAN_TURN、自分の駒 | 選択更新のみ |
| 駒打ち要求 | HUMAN_TURN、自分の持ち駒 | 合法性確認、成り分岐なし |
| 成り確定 | 同じ要求IDのPROMOTION_PENDING | 一度だけ着手確定 |
| AI結果受信 | 同じ対局ID・revision・要求ID、ENGINE_TURN | 合法性再確認後に一度だけ適用 |
| レビュー完了 | 同じ着手レビュー対象 | そのレビューだけ更新 |
| 新局 | 保存と確認済み | 新しい対局ID、前要求を無効化 |
| 待った・分岐 | モードの許可範囲 | 履歴・反復情報も巻戻し |
| 終局 | 有効な終局イベント | 探索・自動応手停止、結果固定 |

単に`positionId`だけ一致で古い結果を受け入れない。同じ盤面へ戻っても、対局ID・履歴revision・要求IDが違えば別要求として扱う。

## 12.2 実装境界

確定手はコントローラ等の単一経路で処理する。Composable内で直接盤・手番・履歴・保存を別々に書き換えない。AI用の探索盤とUIの対局盤を共有ミュータブルオブジェクトにしない。

キャンセル要求後も古い結果は届き得るので、受信側でも検査する。先生の詳細表示や盤面再描画だけで新しいAI応手を起動しない。探索はUIスレッド外、キャンセルは協調的かつ定期的に確認する。

## 12.3 バックグラウンド・エラー

中断時は盤・手番・確定棋譜・時計を保存し、探索を止める。復帰後は未確定の選択をクリアし、最後の確定局面から再開する。AI手番で保存された場合は再開操作後に一度だけ解析する。

エンジン失敗は「解析を再試行」「保存して戻る」を示す。Mockの結果へ無言で差し替えない。保存エラーは現在の対局を保持して通知し、保存成功を装わない。

# 13. 保存・再開・棋譜・振り返り

## 13.1 永続化（P1）

アプリ実行中のメモリだけの履歴を製品完成としない。既存の永続化基盤を優先し、未実装ならRoom等のローカル保存または十分に検証した原子的ファイル保存を採用する。[S12]

保存するもの：対局ID、スキーマ版、RuleProfile、初期局面、先後、モード、難易度、確定手列、結果、時計、日時、現在の閲覧位置、ユーザーメモ、検討分岐、レビューの由来。再計算可能な巨大な探索表を保存しない。

各着手と履歴・時計を同じ整合単位で保存する。保存が終わる前に「保存済み」と表示しない。アプリ終了・プロセス再生成・端末再起動後も最後に保存された確定局面を再開できること。

ViewModelや`rememberSaveable`だけを完全な棋譜保存としない。BundleにはID等の小さい表示状態を置き、棋譜本体は永続層から復元する。[S12]

既存1.0.1のユーザーデータを保持する移行テストを用意する。データ不整合を理由に自動で全削除しない。最後の良好な記録へ復元し、壊れた原本も調査用に保護する。

## 13.2 棋譜一覧

日時、モード、先後、相手難易度、結果、手数、途中か完了かを表示。直近順、タイトル検索、名前変更、選択削除、共有を提供する。削除は対象を明示して確認し、一括消去を初期導線に置かない。

## 13.3 再生・分岐

1手進む／戻る、最初／最後、手数指定、直前手表示、先生コメントを提供する。原本は不変とし、分岐で別手を試す。「本筋へ戻る」を明示する。

「この局面から練習」は元棋譜への参照付きで新しい練習局を作る。対局成績を後から上書きしない。分岐の反復履歴は根元からその経路だけで構成する。

## 13.4 棋譜入出力

P1：G002の完全バックアップ形式（版付き）、KIF系の主要な棋譜の入出力、SFEN局面読込み。CSA／KI2／JKFのフル対応はP2。

- UTF-8の`.kifu`出力を標準とし、従来`.kif`のShift-JIS入力にも対応する。文字化け検出、途中の不正手、形式未対応の理由を表示する。[S21]
- 指し手、成り、不成、駒打ち、同、移動元、終局、手数、名前・日時を扱う。分岐やコメントはG002形式で損失なく保持し、KIFの対応範囲は明示する。
- 初版の最低KIF相互運用は平手本筋・コメント・時間・終局。未対応の分岐を読み飛ばす場合は黙って破棄せず、対応形式への保存を案内する。
- 外部入力は一時領域で検証してから取り込む。失敗で現在の局を上書きしない。ファイルサイズ上限2MiB、手数上限10,000を入力保護の初期値とし、対局の終局手数と混同しない。
- SFENで来歴がない局面は、過去の千日手回数を推測しない。そこを1回目とする新規研究局として扱う。両玉、枚数、行き所等を検証する。
- ファイル入出力はAndroidのシステムピッカーと共有機能を使い、広いストレージ権限を要求しない。[S13]

第三者アプリの非公開データを読むのではなく、権利が明確なライブラリ資料や自作棋譜で相互運用を検証する。

# 14. 音・アクセシビリティ・ヘルプ

駒音は確定手につき1回。候補切替や盤の再描画で連打しない。媒体の音量、消音、Do Not Disturbを尊重し、端末全体の音量を変更しない。触覚は任意設定、長い強振動を使わない。

通常ボタン・持ち駒操作は48dp程度以上のタッチ領域を目安とする。色だけに頼らず、枠・点・文字で意味を伝える。81マスそれぞれに「7六、先手の歩、選択可能」等の読み上げ情報を用意し、Canvasだけで操作不能にしない。[S09][S11]

標準の盤文字、余白、詳細文の文字倍率を独立させ、システム文字拡大で主要操作が消えないようにする。TalkBackで選択→移動→成り選択→持ち駒打ち→レビューを行えることを検証する。

ヘルプには、駒の動き、成り、駒打ち、二歩、打ち歩詰め、王手、終局規則、読み筋と本対局の違い、良否の意味、解析の限界、保存・復元を簡潔に記載する。対局中の文言は自然な敬体とし、ユーザー名を勝手に個人情報から埋め込まない。

# 15. 技術設計とデータ契約

既存の名前・構造を調べ、同役割のクラスを増殖させない。以下は責務の設計であり、必ず同名クラスに作り替える指示ではない。

| 責務 | 主な入力／出力 | 禁止する混在 |
|---|---|---|
| Rules | Position＋Move→合法性／次局面／終局 | Compose依存、先生文章 |
| GameSession | 確定手、履歴、時計、モード | 描画座標での棋譜保存 |
| AnalysisEngine | 不変局面、履歴要約、予算→候補・PV | UIを直接更新 |
| Coaching | 解析＋局面差分→根拠付き説明 | 未検証の指し手生成 |
| Presentation | 表示状態→盤・カード、入力→意図 | 独自成り・駒打ちルール |
| Repository | セッション・棋譜・設定の保存 | UI再描画ごとの全保存 |
| ImportExport | 外部文書→検証済み棋譜 | 無検証の原本上書き |

必要な概念：
- `BoardMove(from,to,promote)`と`Drop(pieceType,to)`。Dropに成りを許す型を避ける。
- `PositionKey`は盤、所有者、成り、持ち駒、手番。手数や表示状態を混ぜない。
- `AnalysisRequest`はgameId、revision、requestId、engineId、engineVersion、budget、root。
- `Candidate`はrootMove、score型、PV、depth、bound、status、origin。
- `CoachingEvidence`は対象マス・手順・確度・根拠の種類。
- `Result`は勝者nullable、理由、宣言・反復等の根拠。

依存ライブラリを更新する場合は互換性とライセンスを確認し、バージョンを固定する。製品改善のためにAndroid Studio全体、他アプリのGradle、グローバルPATHを書き換えない。

# 16. 性能・安定性の合格目標

以下は本書のG002向け目標であり、現行版の測定値ではない。実機基準はmoto g64 5G／Android 15というユーザー報告の端末。実測時は実際のOS・画面・電源・ビルドを記録する。

| 指標 | 初期の合格目標 | 測定条件 |
|---|---|---|
| 駒選択・ボタンの応答 | p95で100ms以内 | アプリ内部の入力→表示、30回以上 |
| 標準先生解析 | 代表30局面でp95 3秒以内 | 候補生成、Cold/Warm区別 |
| 詳細再解析 | 10秒を上限に途中結果と取消を用意 | 完了しないときは打切りを明示 |
| 解析取消 | p95で250ms以内に停止へ向かう | 局面変更・新局・離脱を含む |
| 起動・再開 | p95で3秒以内に盤または意味のある状態 | 初回と通常を分ける |
| UI描画 | 60Hz端末の通常操作で継続的なカクつきなし | Androidの計測で遅延を分析 |
| 連続動作 | 各モード30分以上でクラッシュ・ANRなし | release相当を含む |
| メモリ | 周回ごとの無制限増加なし | 新局・解析・中断の30周回前後を比較 |
| 連続負荷 | 操作不能や熱警告を誘発しない | 温度APIの意味を区別して記録 |

要求→結果、探索本体、UI表示、ADB撮影時間を別に測る。以前の146～323msは報告された一部局面の値であり、全局面・新エンジンの保証に流用しない。数値が速くても棋力基準を満たさなければ不合格。

性能不足はプロファイルで切り分け、予算・キャッシュ・描画を改善する。UIの深い解析を無断で浅くし、間違った先生のまま速度だけを通さない。ネイティブ／GPU導入は必要性を示してから検討する。[S14]

# 17. QA方針 — テスト件数ではなく証跡

## 17.1 四層の確認

1. 純粋ロジック：合法手、盤適用、反復、時計、評価・説明、保存形式。
2. UI／結合：チップ選択→打ち先→着手確定、成りダイアログ、二重入力、先生と相手AIの進行。
3. エミュレータ・実機：描画、入力、Insets、プロセス復帰、音、速度。
4. メル様のHuman Gate：将棋らしく見える、普通に指せる、先生の説明で学べる、通常対局を遊びたいと感じる。

4をCodexが代わりにPASSにしない。1～3をHumanへ丸投げしない。実機未許可でも1～2と専用エミュレータで先行する。

## 17.2 ケースの作り方

- 「自分の実装が返した値」をそのまま正解にしない。明らかな短い手順、公式規則、別実装との比較、独立レビューを使う。
- 各不具合に、修正前に検出できる回帰テストを残す。
- 所有者反転、盤反転、成駒の捕獲→駒打ち、履歴巻戻しを組み合わせる。
- 合法なランダム手列では駒数保存、持ち駒非負、両玉保持、適用→巻戻しの一致を検査する。乱数seedを残す。
- 多数の全局自己対局は時間上限を設ける。終わらなかった局を正常な勝敗へ丸めない。
- 既存87件を維持するが、数だけ増やす目標は設けない。

## 17.3 証跡の形式

要件ごとに `ID / 状態 / commit / build fingerprint / テスト名 / 環境 / 結果 / 画像・棋譜・ログ / 未確認` を記録する。状態は `未着手 / 実装済み未確認 / 自動検証PASS / 実機PASS / Human PASS / BLOCKED / N/A`。

N/Aは本書で条件付きの項目だけに理由付きで使用する。必須機能をN/Aで消さない。テストは成功数・失敗数・エラー数・スキップ数を別に出す。

# 19. 公開候補・署名・プライバシー

## 19.1 公開前に整理すること

正式名は現名称を維持して候補を作り、名称変更の有無だけで他の開発を止めない。applicationIdは維持する。versionCodeを過去へ戻さず、最終候補で既存・公開済み値を確認して単調増加させる。文書版をアプリ版へ流用しない。

Debug、unsigned Release、署名済みRelease、Play配信版を区別する。アップロード鍵とPlay App Signingの配信用鍵を区別し、本番鍵を勝手に作る・流用する・上書きすることは禁止。[S15]

## 19.2 Nativeは条件付き

純粋Kotlin／Javaで必要な品質を達成し、成果物にnativeライブラリがなければ、arm64用`.so`をわざわざ作らない。NDK導入自体を完成条件にしない。

第三者SDKも含めnativeコードがある場合は、ABI、64bit、16KBページサイズ、AABから生成したAPKへの同梱を確認する。エンジンだけでなく全`.so`が対象。実装時のAndroid／Google Play公式要件を確認して適用する。[S16]

## 19.3 Privacyと権限

広告なし・オフラインでも、最終アプリが実際に何を保存・送信するか確認し、PrivacyとData Safetyを整備する。ネットワーク権限、バックアップ設定、依存SDK、ログ、クラッシュ収集を監査し、「ローカルだから何も不要」と断定しない。[S17]

棋譜・設定の自動クラウドバックアップを使うかは明示する。本書の初期方針はアプリ独自のクラウド送信なし。OSバックアップも設定と説明を一致させ、必要なら棋譜を除外してファイル書出しを代替にする。端末間移行とアンインストールで何が失われるかをヘルプへ記載する。

不要なInternet、カメラ、位置、マイク、広いストレージ権限を追加しない。広告・分析SDK・課金は本版に勝手に導入しない。

## 19.4 配布チェック

- エンジン、評価データ、定跡、画像、音、フォント、依存ライブラリの出典・条件・NOTICE。
- Lint：コード上の重大問題0。ツールNPEならログと版を特定し、G002内で安全に解決。広い無効化で隠さない。
- target API等は公開準備時点の公式要求を確認する。過去チャットのSDK値を自動的に最新要求としない。[S22]
- 署名済みRelease相当での新規起動、更新インストール、データ移行、音、AI、指導、保存、復帰。
- デバッグ局面注入、機密値、テスト資産、不必要なログ・Mock表示がReleaseにないこと。
- ストア説明・画像・対象年齢・データ申告が実機の機能と一致すること。
- Google Playへアップロード・公開はしない。最終承認後の別操作とする。

# 20. 完成判定 — 三つの状態を混同しない

**A. 実装候補**：必要コードとビルドはある。未検証を含む。製品完成とは呼ばない。

**B. 製品品質候補**：P0/P1の自動・結合・画面検証が完了し、棋力・指導の基準を満たす。実機/Humanが未完ならその点を明示する。

**C. 製品版Release Candidate**：Bに加えて最新版の実機確認、メル様のHuman Gate、署名済みRelease相当、保存互換、ライセンス、公開準備が揃う。公開済みとは別。

必須不具合の例：持ち駒で成り確認、先後の駒の輪郭が同方向、違法な候補・AI手、局面違いのレビュー、詰みの誤断定、保存消失、終局不能、片方モードがデモ、古い結果混入。いずれかが残れば、見た目や他テスト数にかかわらず製品版不合格。

「競技エンジン級とは言えない」という正直な説明は必要だが、それだけで棋力不足を免除しない。本書の学習・通常対局の実用基準を満たして初めて合格とする。

# 付録A. 平手ルールとアプリ実装の必須チェック

この付録は既存のユーザー提供ルール正本を製品仕様向けに再整理したもの。公式規則の逐語転載ではない。共通規則、採用方式、アプリ独自の入力保護を区別する。[S01–S07][U01]

## A.1 初期配置・座標・移動

通常の先手下側表示では、左から9筋→1筋、上から一段→九段。先手の前は段が減る方向、後手は段が増える方向。所有者を文字や画面位置から推定しない。

初期配置（列は9筋→1筋、下記「玉」は王でも同じ能力）：
```text
一：後香 後桂 後銀 後金 後玉 後金 後銀 後桂 後香
二： ・  後飛  ・   ・   ・   ・   ・  後角  ・
三：後歩 後歩 後歩 後歩 後歩 後歩 後歩 後歩 後歩
四： ・   ・   ・   ・   ・   ・   ・   ・   ・
五： ・   ・   ・   ・   ・   ・   ・   ・   ・
六： ・   ・   ・   ・   ・   ・   ・   ・   ・
七：先歩 先歩 先歩 先歩 先歩 先歩 先歩 先歩 先歩
八： ・  先角  ・   ・   ・   ・   ・  先飛  ・
九：先香 先桂 先銀 先金 先玉 先金 先銀 先桂 先香
```

各20枚、計40枚、持ち駒0。先手から交互に1手。自駒へ移動不可。相手駒のマスへの合法移動は駒取り。パス、盤外、相手駒の操作、二手連続、同じ場所で裏返すだけの手は不可。

| 駒 | 動き（前後は所有者から） |
|---|---|
| 王・玉 | 周囲8方向へ1マス。相手の利きへ入れない |
| 飛 | 縦横へ任意距離。駒を越えない |
| 龍 | 飛の動き＋斜めへ1マス |
| 角 | 斜めへ任意距離。駒を越えない |
| 馬 | 角の動き＋縦横へ1マス |
| 金 | 前・前斜め・横・真後ろへ1マス。後斜め不可 |
| 銀 | 前・前斜め・後斜めへ1マス。横・真後ろ不可 |
| 桂 | 前2段・横1筋の2地点へ跳ぶ。途中の駒を越える |
| 香 | 真前へ任意距離。駒を越えない |
| 歩 | 真前へ1マス。取るときも同じ |
| と・成銀・成桂・成香 | 金と同じ。元の動きを追加で残さない |

## A.2 捕獲・駒打ち・成り

- 捕獲した駒は自分の持ち駒へ。成駒は未成へ戻す。玉は持ち駒にしない。正常局は玉を取る前の詰み等で終了する。
- 持ち駒7種は自手番に空きマスへ1枚だけ打つ。相手駒の上へ打って取れない。0枚、負数、成駒、玉の駒打ちは拒否する。
- **敵陣へ打っても成れない。成り確認を出さない。** 打ち先を成りの理由にしない。後の手番で盤上移動するときは通常の成り判定を行う。
- 成れるのは未成の歩・香・桂・銀・角・飛。先手敵陣は一～三段、後手は七～九段。盤上移動の元または先が敵陣なら任意成りを認める。双方敵陣外なら不可。
- 歩・香の最終段への盤上移動、桂の最終2段への盤上移動は強制成り。銀・角・飛は最終段だけを理由に強制しない。
- 成った駒は敵陣を出ても成りを維持し、捕獲されるまで元に戻さない。
- 同じ筋に自分の未成歩がある歩打ちは二歩。相手歩・自分のと金は数えない。
- 歩・香を最終段、桂を最終2段へ打てない。強制成りで合法化しない。

UIの成り選択はルール層が返した同一from/toの合法候補だけを見る。成り／不成2件なら選択、1件なら確定、0件なら拒否。Dropはこの分岐へ入れない。

## A.3 王手・詰み・打ち歩詰め

自玉の王手を残す／発生させる手は拒否。王手への回避は玉の逃走、王手駒の捕獲、離れた直線王手への合駒などを実際の移動後の盤で判定する。別の利きが残れば回避ではない。桂や隣接王手に合駒は効かない。

玉同士の隣接、ピンを外して自玉をさらす、王手中に無関係な手を指すことは不可。利きの幾何学判定と合法手生成の無制御な相互再帰を避ける。

詰みは王手があり合法な回避がないこと。「評価値が悪い」「玉だけ動けない」「王手された」だけでは詰みでない。通常対局で合法な合駒を詰将棋の無駄合いとして除外しない。

歩を打って、その歩が直接王手し即詰みになる場合は打ち歩詰めで非合法。歩打ち王手でも逃げられる／玉や他駒で合法に取れるなら可。突き歩詰め、歩以外の打ちによる詰みは他の条件を満たせば可。歩打ち王手には間のマスがないため、合駒回避テストを作らない。

まれな王手なし合法手0はまず不正局面・生成漏れを検査し、チェスのステイルメイトとして引分けにしない。到達可能な正常局と確認された場合のG002のアプリ裁定は「合法手なしによる負け」とし、王手された詰みとは別理由にする。公式規則の逐語的な明文と称さない。

## A.4 反復・入玉・時間

- 盤面（所有者・成りを含む）、双方持ち駒、手番が同じ局面の4回目を検出。初期局面を1回と数える。解析・再描画・棋譜閲覧では増やさない。
- 反復区間で片側のすべての手が王手なら、その王手側負け。現在の盤が王手かだけで判断しない。王手が途切れる反復は通常千日手。
- 巻戻し・分岐は経路別の反復履歴を復元。探索用キャッシュへ履歴依存結果を無条件流用しない。
- 本書標準の入玉宣言：自手番・時間内・自玉が敵陣・王手なし・敵陣の自駒が玉を除き10枚以上。点数は敵陣の自駒＋持ち駒、玉0、大駒5、小駒1。成りで点数を増やさない。31点以上勝ち、24～30点指し直し、条件を満たさず正式宣言なら宣言側負け。
- 「条件を見る」だけで宣言したことにしない。正式確定には説明と確認を設ける。
- 本書標準の500手規定は公式の適用条件に従い、500手指了時に王手なら連続王手が途切れたとき適用する。詰みや成立済みの反則を後から上書きしない。
- 合意による24点方式は盤上の全自駒と持ち駒を数える別方式。27点宣言方式は先手28／後手27の別方式。標準宣言の31／24と混ぜない。本版の選択肢へ未実装方式を並べない。
- 投了は確定した側の負け。時間設定がない局に時間切れを作らない。G002の時間処理は第7章に従う。

## A.5 対面ルールとアプリ保護

対面大会の「触った」「駒を離した」「時計を押した」「立会人の裁定」をそのままスマホへ置き換えない。G002では合法手の確定イベントが着手の完了。誤タップの違法入力は局面を変えず拒否し、いきなり反則負けにしない。学習上の待った・ヒントは許可されたモードの仕様として明記する。

棋譜入力・AI出力・UI入力のどの入口でもルールを省略しない。UIが弾いたからモデルに不正Moveが存在してよいとしない。
